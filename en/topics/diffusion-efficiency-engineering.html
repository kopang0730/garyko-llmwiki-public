概述

这一页专门整理 diffusion engineering 这条子主线。它关注的核心问题不是“扩散模型能不能生成”，而是“扩散路线怎样成为一个更可扩展、更可部署、更容易挂接控制能力的工程平台”。在当前知识库里，这条线已经从表示空间、backbone 选择延伸到了采样提速、训练动力学、部署压缩、以及 guidance 接口工程化。

sources/2026-04-14-latent-diffusion-models 的全文复核补上最底层的表示空间工程：固定 A100、同参数和训练步数下，$f=4$–8 是压缩与重建的 sweet spot；inpainting 中 pixel LDM-1 到 LDM-4 VQ 的 train/sample@256/sample@512 throughput 从 0.11/0.26/0.07 提升到 0.33/0.97/0.34，epoch 时间 20.66→7.04 小时。其主干是 U-Net，支持 latent platform 的效率基础，不提供 DiT adoption 证据。

当前综合判断

当前证据已经足够把 diffusion efficiency 看成一张完整工程图谱，而不是几篇互相分散的技巧论文。sources/2026-04-15-all-are-worth-words 与 sources/2026-04-15-scalable-diffusion-models-with-transformers 负责给出 backbone 与 scaling 的起点；sources/2026-04-15-analyzing-training-dynamics-diffusion-models 说明训练动力学本身会决定质量上限；sources/2026-04-16-come-closer-diffuse-faster、sources/2026-04-15-act-diffusion、sources/2026-04-15-distilling-ode-solvers-diffusion-models、sources/2026-04-16-on-distillation-of-guided-diffusion-models、sources/2026-04-15-accelerating-diffusion-sampling-optimized-time-steps、sources/2026-04-15-deepcache 与 sources/2026-04-16-sana-sprint 则把“如何更快生成”拆成更完整的时间纵深：从 2022 年的早期 conditional acceleration，一直到 2025 年的一步一致性蒸馏前沿。

再往后，sources/2026-04-16-high-fidelity-guided-image-synthesis 把高保真 latent guidance 明确抬成独立问题，sources/2026-04-16-post-training-quantization-on-diffusion-models 把这条线推进到低比特部署，sources/2026-04-16-towards-practical-plug-and-play-diffusion-models 与 sources/2026-04-16-self-guided-diffusion-models 又把效率问题和控制问题重新绑在一起：一个降低外部 guidance 接入成本，一个降低 guidance 对人工标签的依赖。放在一起看，diffusion 现在更像一个正在长出完整工程子生态的技术平台。

sources/2026-04-16-plug-and-play-diffusion-features 还补了一层更细的接口工程证据：控制能力可以直接建立在 diffusion feature 复用上，而不只体现在单独的 guidance 模块设计上。

sources/2026-04-16-rethinking-spatial-inconsistency-cfg 还提醒我们，guidance engineering 的难点已经从“接不接得上去”继续推进到“空间上稳不稳定”。

sources/2026-04-16-controlnet、sources/2026-04-16-a-star、sources/2026-04-16-boxdiff 与 sources/2026-04-16-dense-text-attention-modulation 又把这条层次继续拆开：有的路线通过 side-branch adapter 扩展条件控制，有的路线直接在测试时治理 cross-attention，还有的路线把空间布局约束做成 training-free guidance。说明 guidance engineering 已经不是单一技巧，而是一组围绕“接口设计、attention 轨迹与空间一致性”的系统工程问题。

sources/2026-04-16-prompt-to-prompt、sources/2026-04-16-attend-and-excite、sources/2026-04-16-multidiffusion 与 sources/2026-04-16-dlt-layout-transformer 则继续把 control 路线向 composition 层扩张：现在不仅能修 attention、加 box 或 layout，还能把语义完整性、多路径融合和抽象布局建模一起纳入 controllability 叙事。换句话说，diffusion control 正在从若干小技巧逐步长成一套分层接口标准。

sources/2026-04-16-self-correcting-llm-controlled-diffusion-models、sources/2026-04-16-c3net、sources/2026-04-16-layoutdiffusion-graphic-layout-generation 与 sources/2026-04-16-dc-controlnet 又把这套标准往收敛阶段推进：现在已经能看到 controller-based、compound-adapter-based、layout-native 与 hierarchical-control 这几种接口边界开始分明。

sources/2026-04-16-accelerating-dit-gradient-cache、sources/2026-04-16-distilling-parallel-gradients-ode-solvers 与 sources/2026-04-16-text-embedding-quantization-diffusion 则把 deployment / hardware-friendly 这条线真正补厚了：缓存策略开始 DiT-aware，solver 蒸馏开始并行化，quantization 也开始深入到 text-guided 条件链路。

2026-07-12 的全文复核把四篇容易与 DiT 叙事混合的工程论文重新钉在各自层级：sources/2026-04-16-on-distillation-of-guided-diffusion-models 在 U-Net / Stable Diffusion 上联合压缩 CFG 双分支与采样步数；sources/2026-04-16-post-training-quantization-on-diffusion-models 以 U-Net-like CNN 验证 timestep-aware INT8 PTQ；sources/2026-04-16-towards-practical-plug-and-play-diffusion-models 在 ADM / GLIDE 上用分段专家稳定外部 guidance；sources/2026-04-16-self-guided-diffusion-models 依靠 DINO / LOST / STEGO 产生伪条件，再训练 traditional U-Net。四者共同证明 diffusion 工程栈已经覆盖轨迹蒸馏、单步网络压缩、外部控制接口和低标注条件构造；它们属于架构无关或 U-Net 时代的工程证据，不能直接计入 DiT 采用率。

这批全文结果也给出更具体的部署边界：guidance distillation 在 LAION 512 的 2–4 步区间相对 DDIM/DPM++ 优势最明显，到 8 步差距缩小；PTQ4DM 的 A6000 单次网络延迟约改善 1.6–2.3×，同时部分 DDIM 设置的 FID 明显退化；PPAP 仍需 500k 合成图与 300k iterations，data-free 表示免原始标签/数据集访问；self-guidance 的空间控制仍集中在 64×64。当前更可靠的工程判断是：这些模块提供可组合的效率与控制旋钮，每个旋钮都保留训练成本、数据域、硬件和质量边界。

2026-07-12 缓存、路径缩短、一步蒸馏与动态量化复核

  • DeepCache / U-Net reuse：SD v1.5 在 RTX 2080 上约 2.1–2.15× throughput，CLIP 只降 0.05–0.07；LDM 高倍 7–10× 点伴随 FID 4.41–8.23，适合引用的高质量区间是 2.1–4.1×。
  • GOC / DiT cache correction：在 FORA 50% 的相同 2× FLOPs 下，把 FID 6.857 拉回 3.907，A40 latency 只增约 2%；2× 来源是 FORA，GOC 的贡献是误差修正。PixArt/COCO FID 只改善 0.013，跨模型收益差异明显。
  • CCDF / inverse warm-start：MRI 等有观测逆问题可将 1000 NFE 缩到 20，并保持或改善 PSNR；论文没有 wall-clock，$t_0$ 需按任务试验，不能外推为开放式 T2I few-step。
  • SANA-Sprint / one-step distillation：A100、1024²、BF16、batch 1 的 one-step 端到端时间为 0.21s，FID 7.04；transformer-only 0.03s 与 H100 0.10s 属于不同口径。方案仍需 32×A100、25K iterations 的 teacher tuning + distillation。
  • QLIP / prompt-adaptive PTQ：RTX 3090 上相对 W4A16 从 5.58s 降到 4.85s，约 1.15×；W4A8 更快但 FID 28.32，QLIP 以 24.72 换回质量。text embedding 是位宽策略输入，被量化对象是 denoiser activation。

这五篇把“加速”拆成四个必须分开报告的量：NFE、denoiser FLOPs/BitOPs、真实硬件 latency、离线训练/校准成本。Wiki 后续统一禁止只报最大倍数而隐藏质量点、硬件、batch 和额外模型成本。

2026-07-12 条件接口不等于效率复核

  • BBDM：单卡 RTX 3090 可训练不等于轻量；每个域对仍训练 237.09M–258.11M 参数，默认 200 步且未报告 wall-clock/延迟。它属于 diffusion path design。
  • C3Net：所谓效率是避免为每种输入模态组合单独训练 controller；每个输出模态仍保留独立 U-Net/Control U-Net/decoder，论文没有参数量、GPU-hours 或推理延迟。
  • DLT：100-step layout diffusion 在 RICO/PubLayNet 相对 autoregressive baselines 约慢 2×，只在 Magazine 约快 1.65×；核心贡献是属性级 conditioning，不是采样加速。
  • LayoutDiffusion（graphic layout）：条件子任务免重训，但推理仍需 50–200 次 BERT-base 风格 Transformer pass；200 步 FID 2.490，1000 步仍可到 2.295。

这四篇应留在 guidance/interface 工程版图中，但不得用来支撑“低训练成本、低延迟或通用 diffusion acceleration”。今后接口论文也必须分别报告 controller 复用收益、每输出模态模型成本、NFE 与真实 latency。

2026-07-12 Attention control 与闭环控制复核

  • Prompt-to-Prompt：首次系统展示 cross-attention injection/reweighting 能保留构图并局部改 prompt；论文没有定量 benchmark，且真实图依赖不精确 DDIM inversion。
  • Attend-and-Excite：276 prompts×64 seeds，二主体 BLIP 分数从 SD 的 0.767/0.793/0.765 提升到 0.806/0.830/0.811；A100 latency 从约 5.6s 增至 9.7–15.4s。它减少主体遗漏，没有解决关系和计数。
  • A-STAR：segregation + retention 在三类二主体任务达 0.82/0.84/0.82，组合消融优于单项；关系动作仍由 base model 决定。
  • BoxDiff：SD 的 layout AP 2.8→22.3；GLIGEN 29.7→40.2。用户已经提供 box，结果支持 spatial guidance，不代表模型自己理解布局。
  • SLD：DALL-E 3 平均准确率 52.0→78.5，LMD+ 79.3→88.3；Stable Diffusion 一轮/两轮为 54.5/60.0。推理来自 GPT-4、OWL-ViT、SAM 与 diffusion 的检测—规划—修正闭环。

这五篇形成递进栈：attention reuse → token completeness → overlap/retention governance → explicit spatial constraints → external closed-loop controller。前四篇都只在 Stable Diffusion/Imagen U-Net attention 上验证；SLD 的提升来自外部模块系统。它们不能计入 DiT adoption，也不能把执行改善写成 diffusion backbone 原生理解。

2026-07-12 Sampling、训练与 solver 的四种效率变量

  • Optimized Time Steps：固定 denoiser/solver/NFE，只改离散时间点。DiT-XL/2 ImageNet-256 的 5-NFE FID 23.48→8.66，PixArt-α COCO 16.22→9.90；离线 CPU 1.9–14.1s，没有真实生成 latency。
  • D-ODE：冻结 denoiser，按数据集/solver/NFE 用 teacher trajectories 拟合每步标量；CIFAR-10 10-NFE DDIM FID 18.85→8.67。在线 NFE 不变，离线为数 CPU 分钟，仍属于 solver distillation。
  • ACT-Diffusion：训练新的 1-NFE consistency generator + discriminator；ImageNet FID 13.0→10.6，batch 2048→320、steps 800K→400K。缺少 GPU-hours/wall-clock，且大 adversarial weight 会 mode collapse。
  • EDM2：在 ADM U-Net 内重构 magnitude、effective LR 与 post-hoc EMA；ImageNet-512 无 CFG FID 8.00→2.56，XXL CFG 达 1.81。绝对训练预算约 2.147B seen images，63 NFE，作者把 DiT 迁移列为未来工作。

四篇必须分别记为 schedule optimization / solver distillation / one-step model training / training-dynamics engineering。NFE、网络 FLOPs、端到端 latency、离线 calibration/distillation、主训练预算和质量点缺一不可；其中只有 optimized-time-steps 把 DiT/PixArt 当适用 backbone，研究变量仍不是 DiT 架构。

2026-07-12 并行 solver、空间 CFG、条件蒸馏与 wavelet 表示复核

  • EPD-Solver：每个 ODE 区间以 $K=2$ 并行计算两个学习方向；CIFAR/ImageNet 5 Para. NFE 的 FID 分别到 4.33/6.35，但 Para. NFE 是串行 critical path，不是总 denoiser evaluations。单 4090、batch 1 延迟近似不增，不代表 FLOPs、显存、能耗或服务吞吐免费。
  • S-CFG：在 SD/IF U-Net attention 上按语义区域重标 CFG；多数 FID/CLIP 改善较小，人评偏好较明显，单 A100 latency 增约 1.6%–2.9%。它属于 guidance quality governance，不属于 sampling acceleration。
  • CoDi：训练 task-specific conditional U-Net/adapter，把条件适配与 consistency distillation 合并；4-step SR FID/LPIPS 19.637/0.2656 接近 250-step LDM 的 19.200/0.2639，TPUv5 latency 107ms 对 50-step LDM 977ms。代价是每任务训练、364M PE adapter，以及 8-day/64 TPU-v4 的实验上下文。
  • WaveDiff：在 DDGAN-style 2–4 step U-Net 上用 DWT 把空间网格减半；256² FLOPs/显存从 70.82G/3.21G 降至 28.54G/1.07G。它从头训练 adversarial diffusion，速度还来自减深网络，不是现代 LDM/DiT 的通用表示结论。

这四篇把效率账本进一步拆成五个正交量：总 denoiser evaluations、可并行 critical path、单次网络 FLOPs/显存、离线训练/蒸馏预算、质量与条件忠实度。后续禁止把 Para. NFE、training-free guidance、parameter-efficient adapter 或 wavelet FLOPs 降低统称为同一种“加速”。四篇生成主干均为 U-Net/SD/IF/DDGAN 生态，不计入 DiT adoption evidence。

2026-07-12 Spatial/control engineering 的训练—推理转移

  • ControlNet：复制 SD U-Net encoder/middle 构成深侧支；A100 每训练 step 相对 full SD 约 +23% 显存/+34% 时间。冻结主干保护先验，却不是小参数或采样加速。
  • DC-ControlNet：SDXL U-Net 上拆分 intra-element content/layout 与 inter-element order；8×A100 三阶段训练，主文主要是定性证据。FLUX 只生成 DMC-120k 数据。
  • MultiDiffusion：训练为零，每步按 crop/region 多次运行 denoiser 并做最小二乘融合；512×4608 panorama FID 10.3±4.8，调用数随区域/画布增长。
  • DenseDiffusion：SD U-Net 的 training-free cross/self-attention modulation；SOA-I/IoU 77.61/34.99。去 mask-area 后 IoU 升至 38.00，语义出现和自然度反而下降。

控制工程必须同时报告条件忠实、语义出现、自然度、条件冲突、训练存储与推理调用数。四篇均在 Stable Diffusion/SDXL U-Net 验证，不提供 DiT/FLUX 控制适配证据。

P3：feature/guidance engineering 的成本边界

  • FreeU：U-Net decoder backbone/skip 频域重加权；无训练、无额外 U-Net forward/step，但含 FFT/IFFT，缺严格 latency/FLOPs 表。
  • DiffusionCLIP：每目标方向全量微调 DDPM U-Net，41.3s–7min/属性；单图 1.958–10.132s。
  • GradOP+：每图 20–60 次 latent gradients，mixed precision 8.86s，对 SDEdit 4.45s。
  • PnP Features：真实图 1000-step inversion，translation 每步 source/target 两条 U-Net，约 2× forward count。

四篇说明训练成本、checkpoint 数、inversion、U-Net forward 与 latent gradients 必须分栏报告。它们的生成主干均为 U-Net/LDM U-Net。

Inversion/editing P4 继续强化该口径：Blended Diffusion 无训练但每候选约 30s 且每步 CLIP backward；EDICT 无优化但每步两次 denoiser；Imagic 每图 7–8min 适配并从 8 seeds 选结果；Diff-AE 训练吞吐比 DDIM 慢约 20%，还需语义与图像两段 diffusion。training-free / exact / autoencoder / per-image adaptation 都不能直接映射为低部署成本。

CoDi 展示任务专用 few-step distillation：4-step latency 107±3ms 对 50-step 977±1ms，同时 PE-CoDi 每任务仍有364M adapter，实验背景为64 TPU-v4×8天且未拆边际成本。CommonCanvas 约20K A100-hours/run与1120 A100-hours captioning，LayoutDiffusion COCO Full 约216.55 V100-days；少步、开放数据和空间控制都不等于低训练成本。

同时，sources/2026-04-15-diffusion-models-without-attention 依然提供了重要约束：效率工程在强化 diffusion 主线的平台性，但主干路线本身仍存在 attention / non-attention 的结构竞争。这让当前更合理的综合判断变成：diffusion efficiency 的主线已经很清楚，主干架构的最终收敛形态仍值得继续观察。

五层工程栈

0. representation-space 层

这一层回答“denoiser 在什么表示空间运行”。sources/2026-04-14-latent-diffusion-models 证明 mild latent compression 可以同时降低训练和采样成本，$f=4$–8 又显示压缩存在 reconstruction ceiling。Autoencoder 的编码、解码、重建误差和训练成本都属于端到端效率账本。

1. backbone / scaling 层

这一层回答“什么样的主干更适合持续扩展”。当前证据说明 ViT/DiT 路线已经具备很强的平台势能，尤其适合承接后续的效率和控制模块。

2. sampling acceleration 层

这一层回答“怎样减少生成时间”。当前已覆盖 solver、schedule、cache、guidance distillation、多步到少步压缩等多条路线，说明 few-step diffusion 已经从单点技巧发展成系统工程问题。

3. deployment compression 层

这一层回答“怎样让模型更容易部署”。sources/2026-04-16-post-training-quantization-on-diffusion-models 把单步网络成本压缩纳入主线，说明 diffusion 的落地问题已经进入比特宽度和硬件友好性层面。

4. guidance engineering 层

这一层回答“怎样把控制能力更稳定、更低成本地接进系统”。当前已经同时覆盖 guidance 蒸馏、插件化 guidance、自监督 guidance、side-branch condition adapters，以及 test-time / training-free spatial guidance，这说明 controllability 本身也正在被工程化，而不是只靠单一条件器方案。

现在这一层至少可以再细分成六类：一类是 module-level guidance framework，例如 sources/2026-04-16-towards-practical-plug-and-play-diffusion-models；一类是 feature-level control reuse，例如 sources/2026-04-16-plug-and-play-diffusion-features；一类是 side-branch adapters，例如 sources/2026-04-16-controlnet；一类是 inference-time attention / spatial guidance，例如 sources/2026-04-16-a-star、sources/2026-04-16-boxdiff 与 sources/2026-04-16-dense-text-attention-modulation；一类是 compositional / layout control framework，例如 sources/2026-04-16-multidiffusion、sources/2026-04-16-dlt-layout-transformer 与 sources/2026-04-16-prompt-to-prompt；还有一类是 controller / hierarchical control system，例如 sources/2026-04-16-self-correcting-llm-controlled-diffusion-models、sources/2026-04-16-c3net 与 sources/2026-04-16-dc-controlnet。
